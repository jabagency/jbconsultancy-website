# JB Consultancy — Static Website

A five-page static marketing site for JB Consultancy, built with Astro 7 and Tailwind CSS v4, deployed to GitHub Pages. The source is the single authoritative copy of all content and configuration; there is no CMS, no build-time API call, and no client-side data fetching.

## Project structure

```
.
├── src/
│   ├── assets/
│   │   └── brand/          # logo.png (committed; generated by tools/prepare_logo.py)
│   ├── components/         # Reusable Astro components (Header, Footer, ContactForm, …)
│   ├── data/               # Single source of truth for all site content
│   │   ├── site.ts         # Identity, contact details, navigation
│   │   ├── services.ts     # Service offerings
│   │   ├── capabilities.ts # Technology stack / capability matrix
│   │   └── partners.ts     # Partners, clients, and headline stats
│   ├── layouts/            # BaseLayout.astro wraps every page
│   ├── lib/                # Pure, unit-testable business logic (no Astro dependency)
│   ├── pages/              # One .astro file per route (index, about, services, …)
│   │                       #   plus robots.txt.ts, generated so the Sitemap: line
│   │                       #   always matches the deployed origin
│   └── styles/
│       └── global.css      # Design tokens, Tailwind theme, global resets
├── tests/
│   ├── unit/               # Vitest — pure logic and content-shape assertions
│   ├── e2e/                # Playwright — full browser, navigation, forms, a11y, SEO
│   └── build/              # node:test — generated image assets and dist/ output
├── tools/
│   ├── prepare_logo.py     # One-off script to derive all brand images from the source logo
│   └── preview-server.mjs  # Foreground preview server Playwright starts for e2e runs
├── public/                 # Copied verbatim into dist/ (favicons, OG image, logo PNGs,
│                           #   .nojekyll, CNAME → the custom domain)
└── .github/
    └── workflows/
        ├── ci.yml          # Runs on every push/PR to main
        └── deploy.yml      # Deploys to GitHub Pages on push to main
```

**Key architectural idea:** `src/data/*.ts` is the single source of truth for all content. Nothing is duplicated in markup — components read from these modules so that changing a phone number or a nav label is a one-line edit in one file. `src/lib/*.ts` holds the only real logic as pure, unit-testable functions with no Astro dependency, making them straightforward to test with Vitest.

## Testing

The suite has three independent layers:

**Vitest (`tests/unit/`)** — pure logic and content-shape assertions. These test `src/lib/*.ts` functions (URL helpers, form logic, placeholder detection) and verify that `src/data/*.ts` is internally consistent. Fast, no browser, no build needed. Run with `npm test`.

**Playwright (`tests/e2e/`)** — full browser tests against the _built_ output, served by `tools/preview-server.mjs` (Astro's preview server, run programmatically so Playwright owns its lifecycle). Covers navigation, the contact form (including a mocked Web3Forms path), axe-core accessibility, SEO metadata, and responsive layout. Playwright runs both a `desktop-chrome` and a `mobile-chrome` (Pixel 7) project. Both use `channel: 'chrome'`, which means they reuse the system-installed Google Chrome rather than downloading Playwright's own browser bundle. Run with `npm run test:e2e`.

**node:test (`tests/build/`)** — lightweight assertions against `dist/` after a build. Verifies that committed image assets (favicons, OG image, logo PNGs) are present and non-empty, and that the build emitted the expected HTML files. Run with `npm run test:build`.

## Deployment

The site deploys to GitHub Pages using the official first-party GitHub Actions. No third-party deploy action, and no `gh-pages` branch. Production domain: **<https://jbconsultancy.in>**.

**One-time setup:**

1. Push the repository to GitHub (public, default branch `main`).
2. In the repository's **Settings → Pages**, set **Source** to **GitHub Actions** — _not_ "Deploy from a branch". This is the step most often missed.
3. Push to `main`. The `deploy.yml` workflow builds the site and deploys it automatically.
4. Add the DNS records below at the domain registrar.
5. Back in **Settings → Pages → Custom domain**, enter `jbconsultancy.in` and save. Once GitHub's DNS check passes, tick **Enforce HTTPS** (the certificate can take up to an hour to issue).
6. Re-run the latest **Deploy** workflow. The first deploy happens before GitHub knows about the domain, so canonical URLs and the sitemap are built against `*.github.io` until a build runs with the domain in place.

**DNS records** (apex `A`/`AAAA` records point at GitHub's Pages edge; the `www` alias is a `CNAME`):

| Type    | Name  | Value                  |
| ------- | ----- | ---------------------- |
| `A`     | `@`   | `185.199.108.153`      |
| `A`     | `@`   | `185.199.109.153`      |
| `A`     | `@`   | `185.199.110.153`      |
| `A`     | `@`   | `185.199.111.153`      |
| `AAAA`  | `@`   | `2606:50c0:8000::153`  |
| `AAAA`  | `@`   | `2606:50c0:8001::153`  |
| `AAAA`  | `@`   | `2606:50c0:8002::153`  |
| `AAAA`  | `@`   | `2606:50c0:8003::153`  |
| `CNAME` | `www` | `<username>.github.io` |

`public/CNAME` holds the same hostname and is copied verbatim into `dist/`, so the domain survives every deploy even though the artefact replaces the published site wholesale. `npm run test:build` asserts it is a single bare hostname, because a scheme or a stray second line makes Pages silently drop the domain.

**How `SITE_URL` and `BASE_PATH` work:**

`astro.config.mjs` reads these two environment variables to set `site` (used by the sitemap and canonical/OG tags) and `base` (the path prefix for all asset URLs). Both default to the production values, so a local build with no environment set is already correct. The deploy workflow overrides them from `actions/configure-pages`, which reports whatever the repository is actually serving:

- Custom domain (`jbconsultancy.in`) → `base_path` = `/`, `base_url` = `https://jbconsultancy.in`
- User/organisation site (`user.github.io`) → `base_path` = `/`, `base_url` = `https://user.github.io`
- Project site (`user.github.io/repo`) → `base_path` = `/repo/`, `base_url` = `https://user.github.io/repo`

No config file needs editing for any of the three. The same source tree is correct for all of them, which is why the repository can be named anything.

## Regenerating brand assets

Brand images are derived from the source logo by `tools/prepare_logo.py`. Their outputs in `public/` (favicons, `og-image.png`, `logo.png`, `logo@2x.png`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`) and `src/assets/brand/logo.png` are committed to the repository. CI never needs Python or Pillow.

Only run this script if the logo changes:

```bash
# Requires Python 3 + Pillow:  pip install Pillow
npm run assets

# Overwrite existing assets (e.g. after a logo update):
npm run assets -- --force
```

## Browser support and accessibility

The site targets **WCAG 2.2 AA** conformance. axe-core accessibility checks run automatically in CI via Playwright. The stylesheet respects `prefers-reduced-motion` (animations and transitions are suppressed for users who opt out) and `prefers-color-scheme` (automatic dark mode with no JavaScript).
